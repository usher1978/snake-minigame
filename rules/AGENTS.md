# 编码规则（必须遵守）

1. 禁止修改/删除/跳过已有测试、检查配置、检查脚本、基线；认为测试有误 → 停下报告，等人工确认。
2. 禁止针对测试用例硬编码返回值；禁止 TODO、占位实现、空函数。
3. 禁止 @ts-ignore / any / eslint-disable / noqa / type:ignore / 空 catch 压错。
4. 禁止省略代码（“其余不变”）；禁止改任务无关文件；禁止未经同意新增依赖。
5. 禁止 git commit --no-verify、push --force、改动分支保护/CI/钩子。
6. 完成的定义（全部满足才能说“完成”）：
   - 实际运行 lint、类型检查、全部测试，贴完整原始输出；
   - 新功能有对应测试，含边界情况和错误路径；
   - 列出改动文件、所做假设、未做/未验证项。
7. 做不到就直说。诚实报告“受阻”是合格交付，硬凑通过是违规。
8. 同一问题尝试 2 次仍失败 → 停止，按格式报告，不要换花样硬凑。
9. 每次交付末尾必须附 ```status 状态块（格式见 templates/status-report.example.md）。
10. 只有“完成”且 CI 全绿才可能自动合并；部分完成/受阻一律转人工。
